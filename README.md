# Pipidastr VPN

VPN-клиент для **Windows, Android и Android TV** с HTTPS-подписками, выбором приложений и подключением через резервный сервер. Поддерживает VLESS/Reality, VLESS/TLS, шифрованный VLESS и Hysteria2.

На Windows соединение устанавливает [Xray-core](https://github.com/XTLS/Xray-core), а системный TUN создаёт [sing-box](https://github.com/SagerNet/sing-box). На Android и телевизорах используются Android `VpnService` и встроенный [libXray](https://github.com/XTLS/libXray). Для работы нужна собственная подписка или сервер.

[История изменений](CHANGELOG.md) · [Android и Android TV: установка и сборка](AndroidClient/README.md) · [Выпуски](https://github.com/nikitabelkin0001-blip/PipidastorVPN/releases)

> Исходники содержат более новые изменения, чем опубликованный Windows-архив **v0.1.0**. Новые кнопки, поиск резервного сервера и Android 0.6 описаны для текущей версии исходников. Для их получения соберите клиент по инструкции ниже. Готовый Android APK пока не опубликован в Releases.

## Возможности

| Возможность | Windows | Android / Android TV |
| --- | --- | --- |
| HTTPS-подписки и обновление списка серверов | Да | Да |
| Весь трафик или выбранные приложения | Да | Да |
| Тест TCP-задержки серверов | Да | Да |
| Поиск резервного сервера с проверкой HTTPS | Да | Да |
| Работа в фоне | Системный трей | Служба с уведомлением |
| Поиск по списку серверов | Да | На телефоне |
| Импорт QR-кода камерой или из изображения | Нет | На телефоне |
| Передача подписки на ТВ по QR-коду | Нет | Да, с телефона |

На телефоне кнопка подключения остаётся над прокручиваемым списком серверов, настройки открываются кнопкой с тремя полосками. На телевизоре серверы расположены слева, подключение и настройки — справа; интерфейс поддерживает пульт и подсветку выбранных элементов. Приложения показываются со своими иконками, при их отсутствии используется логотип Pipidastr.

## Установка и запуск на Windows

1. Скачайте `PipidastrVPN-portable-win-x64.zip` из [Releases](https://github.com/nikitabelkin0001-blip/PipidastorVPN/releases) либо соберите текущие исходники. Архив **Source code** сам по себе не является готовой программой.
2. Распакуйте весь portable-архив в отдельную папку. Рядом с `PipidastrVPN.exe` должны оставаться `xray.exe`, `sing-box.exe` и остальные файлы сборки. .NET уже включён в portable-версию.
3. Для открытия настроек запустите `Открыть Pipidastr.cmd` либо `PipidastrVPN.exe --show`. Подтвердите стандартный запрос Windows на права администратора.
4. Создайте профиль кнопкой `+`, выберите режим и добавьте свою HTTPS-ссылку кнопкой «Добавить подписку».
5. Выберите сервер и нажмите «Подключить». В режиме выбранных приложений добавьте нужные `.exe` через «Настроить приложения».

В режиме «Выбранные приложения» для работы сайтов через VPN нужно добавить **сам браузер**. После изменения маршрутизации переподключите VPN и перезапустите приложение или браузер. В профиле «Весь трафик» список приложений задаёт исключения.

Крестик окна скрывает клиент в трей, сохраняя подключение. Двойное нажатие значка в трее открывает окно; пункт «Выход» отключает VPN и завершает программу. Обычный запуск `PipidastrVPN.exe` без параметров переключает подключение выбранного сервера; если профиль уже настроен, клиент может запуститься в фоне. Для открытия окна используйте `--show` или командный файл выше.

Для панели Atoll 1.7.1 сохранён [патч кнопки VPN](tools/Atoll-vpn-hold.md): короткое нажатие переключает VPN, удержание открывает окно клиента.

## Установка на Android и Android TV

Соберите APK по [инструкции Android](AndroidClient/README.md#сборка), установите его на устройство и откройте Pipidastr VPN. Добавьте HTTPS-подписку, выберите сервер и нажмите «Подключить». Первый запуск VPN требует подтверждения системного запроса Android.

Если список приложений пуст, через VPN направляется весь трафик. При выборе приложений туннель используется только указанными пакетами. Подключение продолжает работать после выхода на главный экран.

Для передачи подписки на телевизор:

1. На ТВ откройте «Добавить подписку» → «Получить с телефона по QR».
2. На телефоне с Pipidastr отсканируйте показанный QR-код и передайте подписку.
3. Оба устройства должны быть в одной Wi-Fi-сети. Код действует две минуты, ссылка передаётся в зашифрованном виде.

На Android TV значок Pipidastr открывает окно приложения. В изменённом Plume 1.7.1 короткое нажатие отдельной кнопки VPN переключает соединение, удержание открывает клиент. Это интеграция с конкретным лаунчером; её исходный [патч](tools/Plume-v1.7.1-pipidastr.patch) находится в репозитории. На Android 13+ локальная подсеть исключена из VPN, чтобы сохранялся доступ к устройствам домашней сети.

## Проверка серверов и резервный маршрут

- **«Тест пинга»** измеряет время TCP-подключения и показывает результат рядом с сервером. Тест можно остановить. Для Hysteria2 отображается отметка UDP: TCP-проверка для него не выполняется. Доступный порт ещё не подтверждает работу VPN.
- **«Обновить подписку»** загружает актуальный список, сохраняя действующее VPN-подключение.
- **«Найти резервный сервер»** проверяет HTTPS через цепочку **устройство → резерв → выбранный сервер → интернет**. Успешный резерв сохраняется. Выбранный основной сервер остаётся конечной точкой выхода.

На Windows поиск использует отдельные временные процессы Xray, привязанные к физическому Wi-Fi/Ethernet, и не отключает действующий туннель. Если прямое подключение основного VLESS-сервера не отвечает, клиент использует сохранённый резерв. Поиск резервного маршрута в Windows поддерживается для VLESS.

На Android поиск переподключает VPN: встроенное ядро проверяет кандидатов последовательно. Если прямой маршрут не передаёт HTTPS, клиент пробует VLESS-резервы; ранее найденный проверяется первым. Подключение или поиск можно остановить кнопкой «Отменить». Проверка требует HTTPS-ответ с IP-адресом, а используемый резерв показывается в статусе.

Доступность зависит от подписки, сервера и сети. Поддержка формата ссылки не означает, что каждый сервер сейчас отвечает; резерв также не восстановит отключённый удалённый сервер. Число серверов определяется актуальной подпиской.

## Discord и Zapret на Windows

`Discord.exe` и Zapret `winws.exe` по умолчанию направляются напрямую. При обновлении профилей Discord переносится из списка приложений через VPN в прямые исключения. Диапазон `162.159.128.0/17` исключён из системного маршрута TUN для совместимости с Zapret. Сам Zapret нужно запускать отдельно.

TUN использует смешанный стек: TCP обрабатывает Windows, UDP — gVisor. Клиент создаёт IPv4-маршрут; DNS идёт по HTTPS через VPN. UDP-сессии сохраняются до 15 минут бездействия. Работа Discord на других адресах также зависит от правил и версии Zapret. После изменения профиля полностью перезапустите Discord.

## Диагностика и настройки

**Windows:** журнал находится в `%LOCALAPPDATA%\PipidastrVPN\session.log`; после 2 МБ предыдущая запись переносится в `session.log.old`. В журнале могут быть адреса посещённых сайтов — проверяйте содержимое перед публикацией.

Перед запуском TUN клиент проверяет HTTPS через сервер. При ошибке назначения IPv4 он повторяет запуск TUN до двух раз. Xray и sing-box привязаны к процессу клиента через Windows Job Object: при аварийном завершении Windows завершает и движки, освобождая адаптер. Если ошибка адаптера повторяется, проверьте компонент TCP/IPv4 и перезагрузите Windows.

Профили и серверные ссылки хранятся в открытом виде в `%LOCALAPPDATA%\PipidastrVPN\profiles.json`, идентификатор устройства — в `device-id.txt`. Не публикуйте эти файлы. Для удаления portable-клиента завершите его через трей и удалите папку сборки; настройки хранятся отдельно.

**Android / Android TV:** этапы подключения и ошибки доступны через ADB:

```shell
adb logcat -d -s PipidastrVPN
```

Подписка и настройки находятся в закрытом хранилище приложения; резервное копирование отключено. При ошибке `UnknownHostException` не удаётся разрешить адрес сайта через текущий маршрут. Проверьте прямое подключение и резерв: такая ошибка может быть следствием того, что сервер вообще не передаёт трафик.

Если подписка требует HWID, клиент создаёт постоянный случайный ID устройства и повторяет запрос. Провайдер может учитывать клиент как отдельное устройство; при исчерпанном лимите место нужно освободить в кабинете провайдера.

## Сборка и проверки

### Windows

Нужны Windows x64 и .NET SDK 9. Движки и их лицензии находятся в `VpnClient/third_party`.

```powershell
dotnet publish VpnClient/VpnClient.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish/windows
dotnet run --project VpnClient.SmokeTests/VpnClient.SmokeTests.csproj -c Release
```

Распространяйте всю папку `publish/windows`, включая движки и лицензии. Smoke-тесты проверяют импорт подписок, разбор ссылок, маршрутизацию, конфигурации движков, TCP-проверку и завершение дочерних процессов через Job Object. Для сетевых проверок нужен доступ к локальным сокетам.

### Android / Android TV

Нужны JDK 17, Android SDK Platform 35 и Build Tools 35. Поддерживаются ARM64 и ARMv7, минимальная версия Android — 8.0. Загрузка проверенного `libXray.aar`, сборка и установка APK описаны в [AndroidClient/README.md](AndroidClient/README.md#сборка).

В репозитории используются [sing-box 1.14.4](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4), [Xray-core 26.11.9](https://github.com/XTLS/Xray-core/releases/tag/v26.11.9) и [libXray 26.11.9](https://github.com/XTLS/libXray/releases/tag/v26.11.9). При распространении сборок сохраняйте лицензии зависимостей. Клиента для iOS в репозитории пока нет.
